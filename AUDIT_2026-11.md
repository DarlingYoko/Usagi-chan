# Usagi-chan Audit — 2026-11-12

Third pass, after `REFACTOR_PLAN.md` (2026-06, security/performance) and
`IMPROVEMENT_PLAN.md` (2026-06, reliability/i18n/tests) were both fully
implemented and the Music cog was split (PR #50). Scope: every cog, `src/`,
the DB layer, migrations, infra, CI, dependencies and i18n, on `universal`.
Nothing already fixed by the earlier plans is repeated here. The key findings
of each area were re-checked against the code; items marked _(unverified)_
depend on library or panel behaviour that couldn't be run locally.

## Score

| Area | Score | Why |
|---|---|---|
| Security | **6/10** | The infrastructure is hardened (SSRF guard, encryption, non-root), but permission checks inside features have holes: auto-roles can hand out roles above the moderator's own, a moderator can make `@everyone` a moderator role, pins and birthday timers need no permissions, the bot reposts `@everyone`, other users can file VPN renewals on your profiles, and `/music play` fetches arbitrary internal URLs. |
| Correctness | **6/10** | Settings tables have no unique constraints. Daily-claim results are last-write-wins. VPN renewal math isn't tied to what was paid. |
| Reliability | **6/10** | Loops are guarded. Still missing: compose `restart:`, startup caches that survive a failed first load, idempotent daily jobs across restarts, HTTP timeouts in Endfield. The Music player can't recover from a crashed task. |
| Data | **6/10** | Fernet was added without a backfill (old rows are still plaintext). A wrong key passes ciphertext through silently. There is no cleanup when the bot leaves a guild, and several tables only grow. |
| Ops / CI | **5/10** | The env template doesn't match the code. CI never runs migrations against a real Postgres, and there is no lint, type, dependency or secret scan. Dev-tool leftovers are in the runtime requirements. |
| Structure | **7/10** | Music is split. Six files are still over 500 lines: Main 957, arknights_utils 810, Hoyolab 728, Endfield 634, wordle_utils 583, VPN 533. |
| i18n | **8/10** | en/ru parity is exact (201/201) and no key is missing. Remaining: hardcoded strings in loops and listeners, and a few ru values left in English. |

**Overall: 6/10.** No critical bugs. The weakest axis is now permission
logic inside features, not infrastructure. Phase 1 is a set of small, local
diffs.

## Phase 1 — Security (do first, small diffs)

- [ ] **1.1 Auto-role privilege escalation.** `Main/index.py:452-521` (add), `:630-702` (edit role); grant at `Events/index.py:363-367`. Only `check_member_is_moder` is checked. A moderator without admin can bind `@Admin` (or any role below the bot) to a reaction and give it to themselves. Fix: reject unless the invoker is owner/admin **and** `role < ctx.author.top_role`, `role.is_assignable()`, the role is not managed or the default role, and it has no `administrator`/`manage_*` permissions.
- [ ] **1.2 Moderators manage the moderator list.** `Moderation/index.py:39-40, 257-327`. `/setup role add|remove` is moder-gated. Adding `@everyone` (id == guild id) makes every member a moderator (`UsagiChecks.py:61`). Fix: require `administrator`/`manage_guild` or owner, and reject `guild.default_role`.
- [ ] **1.3 No global mention policy.** No `allowed_mentions` anywhere. "Add Based Message" (`Fun/index.py:178-184`) reposts `message.content`, so `@everyone`/role pings are re-fired by the bot. Fix: `allowed_mentions=AllowedMentions(everyone=False, roles=False, users=True)` on the bot constructor; also truncate the reposted content (2000-char limit).
- [ ] **1.4 Missing permission checks.**
  - `Tech/index.py:30-36`: "Pin message" works for anyone, using the bot's Manage Messages permission.
  - `Birthdays/index.py:215-251`: `toggle_timer`/`add_timer` let any member point the hourly channel rename at any voice channel.

  Fix: `manage_messages`/`check_member_is_moder`.
- [ ] **1.5 Guild-only commands run in DMs.** `UsagiChecks.py:56`, `Moderation/index.py:40`, `Main/index.py:151`. `ctx.guild is None` causes an AttributeError, which goes to the generic error branch and DMs the owner, so anyone can spam the owner. Fix: set guild-only contexts bot-wide (or per cog), plus a `ctx.guild` guard in the checks. _(Default contexts in py-cord 2.8 are unverified.)_
- [ ] **1.6 VPN renewals on someone else's profiles.** `/vpn request` posts `VpnRenewView` publicly (`VPN/index.py:446`), and `VpnRenewButton.callback` (`:164-168`) never checks `interaction.user`. Another member can file requests for your profiles; rejecting them also wipes your real pending ones. Fix: `ephemeral=True` plus an author check.
- [ ] **1.7 `/vpn renew` treats any decision except the exact `"Rejected"` as approval.** `VPN/index.py:336-346`. The option is autocomplete-only, so typing `reject` extends the subscription. Fix: `choices=[Approved, Rejected]` and an explicit `== "Approved"` branch.
- [ ] **1.8 SSRF via `/music play`.** `Music/enqueue.py` `_enqueue_direct`: any non-YouTube URL is fetched by the yt-dlp generic extractor, then by ffprobe/ffmpeg. That includes `127.0.0.1`, the compose network (Postgres, 3x-ui) and metadata IPs. This violates the "validate user URLs" rule in CLAUDE.md. Fix: before extraction, run the `UsagiNet` host validation (scheme http/https, public IPs only).
- [ ] **1.9 User-controlled `local@` marker.** `voice_state.py:143`, `seek.py:57`. `local@` was the prefix of a removed upload feature; nothing produces it any more. A link like `local@/path/file.mp3` passes yt-dlp (it falls back to search), gets queued with `url=link`, and the player then opens `/path/file.mp3` from the container's filesystem. Fix: delete the `local@` branches (and the dead `./tempMusic` cleanup in `index.py:43`, `music_utils.py:180`).
- [ ] **1.10 SSRF guard is DNS-rebindable.** `src/UsagiNet.py:59-60`. The IP is validated, then aiohttp resolves the name again to connect (TOCTOU), so a TTL-0 domain can swap in `169.254.169.254`. Fix: do the validation inside a custom `AbstractResolver` passed to `TCPConnector(resolver=...)`.
- [ ] **1.11 Encryption-at-rest gaps.** `db/types.py:43-49`.
  - (a) There was no backfill when Fernet landed (9311288). Pre-2026-06-12 Hoyolab cookies, Gryphline tokens and VPN uids stay plaintext until rewritten, and their update paths never rewrite them. Fix: a `0002` data revision that reads and rewrites every `EncryptedText` column.
  - (b) A wrong or rotated key makes `InvalidToken` return the **ciphertext as plaintext**. It is then sent to the HoYoLAB, SKPort and 3x-ui APIs and built into sub URLs, with nothing logged. Fix: pass a value through only when it doesn't look like a Fernet token (`gAAAAA`); otherwise log and raise.
  - (c) The key is only checked lazily. Fix: validate it in `before_identify_hook`; use `MultiFernet` with comma-separated keys for rotation.
- [ ] **1.12 Postgres container gets every secret.** `docker-compose.yaml:13-14`: it loads all of `stack.env` (Discord token, Fernet key, VPN creds). Fix: a separate env file with only `POSTGRES_*`.

## Phase 2 — Correctness & data integrity

- [ ] **2.1 Duplicate rows on double submit.** "One per entity" tables are check-then-insert with no unique constraint, and `ModelAdmin.get()` has no ORDER BY.
  - Tables missing a unique constraint: `usagi_language.user_id`, `usagi_config(guild_id, command_tag)` (the index is non-unique), `usagi_save_roles.guild_id`, `usagi_birthday_timer.guild_id`, `usagi_endfield_profile(guild_id,user_id)`, `usagi_wordle_results(guild_id,user_id)`, `usagi_vpn_users.sub_name`.
  - Fix: a dedupe-then-constrain revision and `ON CONFLICT` upserts in the settings paths.
  - **Not a bug: Hoyolab and Endfield logins.** One user may own several game accounts, so every login creates a new row by design (owner decision, 2026-11-13). Still worth fixing: the Endfield `LoginModal` (`ArknightsEndfield/index.py:113-148`) makes ~5 SKPort calls before it responds, so the interaction can expire. Defer it first.
- [ ] **2.2 VPN renewal money logic.** `VPN/index.py:104-149, 363-423`, `schemas.py:40-52`.
  - (a) `subscriptions_count` is free input, not `len(profiles)`, and the amount paid is never stored or shown to the owner.
  - (b) Approval applies **every** pending row of the user, in arbitrary order, so a corrected request and the original both apply, and double payments don't stack.
  - (c) The approval `update_all` matches by `sub_name` across all users (`:402`).
  - Fix: store `amount` and `vpn_user_id` on the request, approve by request id, and supersede older pending requests for the same profile.
- [ ] **2.3 VPN unlimited profiles crash the renewal modal.** `VPN/index.py:116`: `max(None, datetime.now())` raises TypeError. `/vpn request` includes unlimited profiles. Fix: treat None as now, or exclude those profiles.
- [ ] **2.4 Hoyolab daily-claim result is last-write-wins.** `Hoyolab/index.py:480-502`.
  - `"InvalidCookies"` from Genshin is masked by StarRail's `False`.
  - `"GeetestTriggered"` is truthy, so it is announced as "Claimed".
  - A network error on Genshin skips the StarRail and ZZZ claims.
  - The announcement names a non-existent command (`:508`).
  - Fix: a per-game result with per-game try/except.
- [ ] **2.5 Endfield treats HTTP 403 as "Already signed".** `arknights_utils.py:524`: dead tokens are reported as success. `msg.lower()` also crashes on a null message. Fix: only an explicit already-signed code/message counts; `str(data.get("message") or "")`.
- [ ] **2.6 Endfield profile maths and selection.** `arknights_utils.py:762-774`: lost sanity is computed from a split negative timedelta (90 min over shows 150). `index.py:59-82`: the select option has no `value`, so duplicate nicknames make Discord reject the component and a `None` nickname raises IndexError. Fix: use `total_seconds()`; `value=str(uid)`.
- [ ] **2.7 One bad account blanks `/endfield profile|sanity`.** `index.py:325-349, 417-425`: the first failing account returns for all. The profile command defers publicly, so its "ephemeral" errors are public. Fix: per-account errors, and a consistent `defer(ephemeral=...)`.
- [ ] **2.8 Missed birthday is never retried.** `Birthdays/index.py:70-92,116`: exact `date == today` match, and the date only rolls forward after a successful send. Downtime at 12:00 MSK means that person is never congratulated again and is skipped by the timer. Fix: `date <= today` and roll forward until it's in the future.
- [ ] **2.9 Auto-role remove/edit on deleted things.**
  - `Main/index.py:399-412`: `fetch_message` runs outside the try, so a hand-deleted message leaves the DB and cache rows forever. The error path also uses `send_followup` with no prior response (`test_main.py:64` asserts this bug).
  - `:577-597`: `old_emoji is None` leads to `clear_reaction(None)`; numbering skips the removed row; `get_roles_from_message` crashes on deleted roles.
  - `Events/index.py:364-377,398-411`: `add_roles(None)` for deleted roles, and a public red embed on every reaction when Forbidden.
- [ ] **2.10 Role restore on rejoin is all-or-nothing.** `Events/index.py:275-281`: there is no `is_assignable()` re-check at rejoin, so one role now above the bot means none are restored. It also restores moderator roles after a kick or ban. Fix: filter assignable roles; consider excluding moderator roles.
- [ ] **2.11 Wordle end-of-game.**
  - `wordle_utils.py:572-576`: the primary key is assigned by hand (`id=last.id+1`), the same anti-pattern removed from Events in 3.2. Concurrent finishes collide and the sequence never advances.
  - `:515`: `fetch_member` raises NotFound for a departed creator before scoring.
  - `:79,131-147`: no `finished` guard, the lose check is `== 0` (lives reach −1), and two simultaneous winners both score.
  - Also: `ModelAdmin.get_last_obj` (`db/models.py:156-160`) has no LIMIT, so it loads the whole table.
- [ ] **2.12 Music player can't recover.**
  - `voice_state.py`: when `generate_source` fails, `current` becomes the string `"error"`. `/music now|queue|pause` then raise AttributeError on `"error".source`. With loop on, the player task itself dies on `self.current.source.url`.
  - `get_voice_state` "recovers" via `recreate_bg_task` → `__init__`. That wipes the queue and sets `voice=None` while the bot is still connected. Then `/music play` → `connect_author_channel` returns True (already in the channel) without restoring `voice`, and `play` silently does nothing until `/music musicreload`.
  - Fix: keep `current=None` on error; recreate only the task, not the whole state; re-attach `voice = guild.voice_client` when it is missing.
- [ ] **2.13 Music `after=` callback isn't thread-safe.** `voice_state.py:322-341`: `play_next_song` runs in py-cord's audio-player thread and calls `asyncio.Event.set()` directly. That doesn't wake the event loop, so a song transition can stall until the next gateway event. Fix: `self.bot.loop.call_soon_threadsafe(self.next.set)`.
- [ ] **2.14 Small ones.**
  - Tech: a unic role deleted by hand blocks the user forever (`Tech/index.py:105-111`), and the autocomplete calls `fetch_roles()` per keystroke.
  - Birthdays: the remove autocomplete crashes on departed members (`:39-41`).
  - Twitch: `follow_streamer` uses `self.twitch` before the first auth, so it is `None` (`:155`).
  - `/music remove` with an index past the end raises IndexError (`queue_commands.py:66`).
  - VPN `"Time data does not match format"` shows `%m.%d` while the parser uses `%d.%m`.
  - Abyss reset date assumes the 1st and 16th (`genshin_utils.py:294-297`; only the 16th since 4.7).

## Phase 3 — Reliability & operations

- [ ] **3.1 Containers don't come back.** `docker-compose.yaml`: no `restart:` policy and no Postgres healthcheck; `depends_on` only waits for the container to start. Fix: `restart: unless-stopped`, a `pg_isready` healthcheck, `condition: service_healthy`. _(Skip if Portainer/CapRover already restarts them.)_
- [ ] **3.2 Env template doesn't match the code.** `example-usagi-variables.env` has `BOT_TOKEN`, `VPN_API_LOGIN_URL`, `VPN_API_GET_LIST_URL`; `env.py` reads `DISCORD_TOKEN`, `VPN_API_URL`, `VPN_SUB_URL`. A deploy from the template runs `bot.run(None)`.
- [ ] **3.3 Startup caches can stay unset.** `Events/index.py:103-110`, `usagi.py:27-29`: `_ready_once=True` is set before the loads, and the caches have no `{}` defaults. One DB error on first connect leaves AttributeError on every command until restart. Fix: defaults in `__init__`, and set the flag only after the loads succeed.
- [ ] **3.4 Daily jobs repeat after a 19:xx restart.** `Hoyolab/index.py:389-394,446-451`, `ArknightsEndfield/index.py:223-229`: hourly loops gate on `hour == 19` with no "already ran today" record. Fix: store the last-run date per job.
- [ ] **3.5 External HTTP robustness.**
  - Endfield `ClientSession` has no timeout (the default 300 s) and calls `r.json()` without checking the status (`arknights_utils.py:172, 465, 499`).
  - `genshin_utils.get_user_data` lets `ClientError`/`TimeoutError` escape, which breaks `/hoyolab delete` when HoYoLAB is down (`:71-93`).
  - `check_cookies` validates against a stranger's UID 701700971 (`:22,56`); if that player goes private, all logins fail. Use `get_hoyolab_user()` instead.
- [ ] **3.6 Interactions that outlive 3 s.** No `defer` before slow work:
  - `/vpn renew` and `create_user` (panel calls; the sub URL can be lost);
  - `/endfield set_bg` (`fetch_image` up to 15 s);
  - auto-role add/remove (`Main/index.py:383,452,548`);
  - the `/music queue` busy-wait while a song resolves.
- [ ] **3.7 VPN views expire after 180 s.** `VPN/index.py:187-191,252`: the renewal button in the hourly DM fails once the view times out, and `notified=True` means the DM is never re-sent. Fix: `timeout=None`, persistent `custom_id`s, and `bot.add_view` at startup.
- [ ] **3.8 Error handling order.** _(Partly done in `73fc34e`: an expired interaction, code 10062, is now only logged and no longer pages the owner.)_ `Events/index.py:246-252`: the owner DM is sent before the user reply, so if the owner's DMs are closed the user sees "interaction failed". `:174-187`: prefix-command errors arrive wrapped in `CommandInvokeError`, and `commands.CheckFailure`/`UserInputError` aren't routed, so typos DM the owner. Fix: reply first, guard the owner DM, unwrap `.original`.
- [ ] **3.9 Gateway behaviour.**
  - `usagi.py:59-65`: `before_identify_hook` never calls `super()`, which drops py-cord's 5 s re-identify backoff.
  - `Events/index.py:126`: an explicit `sync_commands()` runs on top of py-cord's `auto_sync_commands` on every connect.
- [ ] **3.10 Data lifecycle.**
  - There is no `on_guild_remove`, so configs and encrypted credentials of guilds the bot left are kept forever and still loaded by the loops.
  - Nothing flushes `messages_dump` on shutdown, so each deploy loses up to 30 minutes of stats.
  - Expired `usagi_timer` rows are never deleted; their channels are renamed every 10 minutes forever, and the loop has no `before_loop`/`wait_until_ready`.
  - `usagi_member_roles` rows are never removed after restore.
  - `usagi_backup` is written but never read.
- [ ] **3.11 Endfield sanity loop retries dead tokens forever.** `ArknightsEndfield/index.py:184`: 4+ auth calls per hour per dead token, with no user notice. Fix: mark the account dead after N failures and tell the user once.
